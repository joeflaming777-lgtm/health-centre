⚖️ Priority Scheduling Engine Specification

The core engine operates a deterministic multi-key min-heap built with Python's heapq algorithm. Patients waiting in the emergency queue are continuously ordered by the tuple:

Key = (priority_rank, arrival_timestamp, registration_sequence)

Clinical Triage Hierarchy:

  • Priority 1 (Critical): Immediate resuscitation, cardiac arrest, respiratory failure. Target wait: ≤ 15 mins.
  • Priority 2 (High): Emergent care, suspected appendicitis, open fractures, acute burns. Target wait: ≤ 30 mins.
  • Priority 3 (Medium): Urgent, severe migraine, lacerations, asthma exacerbation. Target wait: ≤ 60 mins.
  • Priority 4 (Low): Non-urgent, minor abrasions, sprains, suture removal. Target wait: ≤ 120 mins.

Tie-Breaking and Concurrency Protection:

When patients share the same priority rank, earlier arrival timestamp serves as first-come-first-served tie-breaker. If both priority and arrival timestamps coincide, the deterministic database registration sequence (primary key) breaks ties. All resource assignments execute within atomic BEGIN IMMEDIATE database transactions to prevent race conditions.
